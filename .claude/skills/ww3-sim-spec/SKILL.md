# ww3-sim-spec

1 つのシミュレーション = 1 つのケース `runs/<case>/`。その中心が仕様書 `runs/<case>/SPEC.md` で、
設定ファイル (`input/`)・実行 (`run.sh`)・ポスト処理 (`postprocess.sh`) は仕様書に合わせて作る。

```
runs/<case>/
  SPEC.md          仕様書 (一次の出典)。テンプレートは references/spec_template.md
  run.sh           実行 (skill ww3-run-config の手順 5)
  postprocess.sh   ポスト処理。仕様書 10.2 節の図の表どおり (skill ww3-postprocess)
  input/           設定ファイル。仕様書の「設定ファイル・キー」の列どおり
  work/            出力 (ignore)。図は work/figs/
```

| やりたいこと | 見るもの |
|---|---|
| 仕様書を書く | [`references/spec_template.md`](references/spec_template.md)、記入例 `runs/sample-jonswap/SPEC.md` |
| 各項目の値と設定ファイルのキーを決める | skill `ww3-run-config` (設定ファイルの一覧) |
| 図の種類・ツール・NetCDF の約束事 | skill `ww3-postprocess` |

## 進め方

1. **仕様書を書く**: テンプレートの「---」より後を `runs/<case>/SPEC.md` にコピーして埋める。
   - 値は skill `ww3-run-config` を見て決め、「設定ファイル・キー」の列に対応するキーを書く。
   - 時間刻みは CFL の計算を 7 節に書く。
   - 10.2 節に作る図を ID (V1、V2 …) つきで並べ、各図の「確かめること」を書く。
   - 11 節に受け入れの基準を書く (結果の欄はまだ空)。
2. **設定ファイルを書く**: 仕様書の表どおりに `input/` を作る (`ww3-run-config` の手順 2〜4)。
   switch は `input/switch_<case>`、データは `../input/<file>` で参照する。
3. **実行する**: `./dev build runs/<case>/input/switch_<case>` → `./dev docker run -- bash runs/<case>/run.sh`。
4. **ポスト処理をする**: 10.2 節の表どおりに `postprocess.sh` を書き (1 行 = 1 図、行末のコメントに ID)、
   `./dev docker run -- bash runs/<case>/postprocess.sh` で図を作る (`ww3-postprocess`)。
5. **検証して記録する**: 11 節の基準を確かめ、結果の欄に日付・値・確かめ方 (コマンドや図) を書く。
   満たさなければ、原因を調べて仕様書か設定を直す (2 へ戻る)。
6. **設定を変えるとき**: 仕様書を先に直し、12 節に日付・変更・理由を書いてから、設定ファイルと `postprocess.sh` を直す。
   やり直す範囲は `ww3-run-config` の「設定を変えるとき」。

## 決まり

- 仕様書が一次の出典。設定ファイル・`run.sh`・`postprocess.sh` の値は仕様書と一致させる。食い違いを見つけたら、
  どちらが正しいかを決めて両方をそろえ、12 節に書く。
- 値には単位を付ける。方向は「来る方向 / 向かう方向」と「北から時計回り / Cartesian」を書く
  (WW3 は入力・出力ごとに規約が違う。`ww3-run-config` の「共通の約束事」)。
- 使わない項目も行を残して「なし」と書く。
- 10.2 節の図の ID と `postprocess.sh` の行は 1 対 1 にする。図を足す・消すときは両方を直す。
- 確かめていないことは「未確認」と書く。11 節の結果は、実際に確かめたことだけを書く。
- 大きなデータ (NetCDF など) は commit しない (`*.nc` は ignore)。取得元と作り方を 3〜6 節に書く。

## レビューの観点

ケースをレビューするとき (新規・変更のどちらでも) に確かめる:

- 仕様書の各表の値と、「設定ファイル・キー」の列が指す設定ファイルの値が一致している
  (特に格子の範囲・解像度、スペクトル格子、時間刻み、期間、出力の変数と間隔)。
- 時間刻みが CFL 条件を満たし、計算が 7 節に書かれている。DTMAX・DTKTH・出力の間隔の関係も妥当か。
- 方向の規約と単位が正しい (ww3_strt の ITYPE 1・2 の θm、`jonswap_strt --from-deg`、一様な強制場は来る方向。
  ITYPE 4 の値の並びと NetCDF のスペクトルは向かう方向で、ITYPE 4 は Cartesian、NetCDF は北から時計回り)。
- 境界の扱い (境界点の位置、スペクトルの出典、それ以外の外周) が書かれ、設定と合っている。
- `switch_<case>` のパッケージと、物理 namelist の group が合っている (コンパイルしていない group は無視される)。
- 10.2 節の図の表と `postprocess.sh` が 1 対 1 で、各図に「確かめること」がある。
- 11 節に基準があり、結果が日付と確かめ方つきで書かれている。
- 12 節に変更が記録されている。

## 使わない場面

- 設定ファイルの書き方・キーの意味を調べる → skill `ww3-run-config`
- 図を作る・ツールを足す・NetCDF の変数を調べる → skill `ww3-postprocess`
- Fortran ソースの変更や regtest → LLM.md §4〜§6

## このスキルの保守

このスキルとテンプレートは使いながら直していく。

- 使っていて**不足** (テンプレートに無い節・項目、書き方の決まりの抜け) や**誤り** (テンプレートどおりに書いて困ったこと) に
  気づいたら、その作業の中で SKILL.md とテンプレートを直す。記入例 (`runs/sample-jonswap/SPEC.md`) も合わせる。
- 書く前に確かめる。根拠はソース・テンプレートの `file:line` か、実際に動かした結果にする。確かめていないことは書かないか、
  「未確認」と明記する。
- 直したことは、その作業の報告でユーザーに伝える。他の skill (`ww3-run-config`・`ww3-postprocess`) や LLM.md と食い違ったら、
  両方を直す。
